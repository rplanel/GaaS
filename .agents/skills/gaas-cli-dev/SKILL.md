# gaas-cli developer guide

This skill helps you develop `gaas-cli`, the Python command-line toolkit for GaaS located in `packages/gaas-cli/`.

## Project overview

- **Runtime:** Python 3.13+
- **CLI framework:** Typer
- **Output:** Rich
- **Validation:** Pydantic
- **Package manager:** `uv` (do not use `pip` directly)
- **Versioning:** `uv-dynamic-versioning` with git tag prefix `gaas-cli-`
- **Entry point:** `gaas = "gaas_cli.main:app"` in `pyproject.toml`
- **Auto-generated:** `src/gaas_cli/_version.py` — never edit by hand

## Project structure

## Adding a new top-level command group

1. Create a new package under `src/gaas_cli/`:

```bash
mkdir -p src/gaas_cli/newgroup
touch src/gaas_cli/newgroup/__init__.py
```

2. Define the Typer app in `src/gaas_cli/newgroup/__init__.py`:

```python
import typer
from rich.console import Console

console = Console(stderr=True)

app = typer.Typer(no_args_is_help=True)


@app.command()
def hello(name: str):
    """Say hello."""
    console.print(f"Hello {name}")
```

3. Register it in `src/gaas_cli/main.py`:

```python
import gaas_cli.newgroup as newgroup

app.add_typer(
    newgroup.app,
    name="newgroup",
    help="New group commands.",
)
```

4. Verify:

```bash
uv run gaas newgroup --help
uv run gaas newgroup hello World
```

5. Lint and format:

```bash
ruff check src/gaas_cli/newgroup/ src/gaas_cli/main.py
black src/gaas_cli/newgroup/ src/gaas_cli/main.py
```

## Adding a command to an existing group

Add an `@app.command()` decorated function in the relevant `__init__.py`. Use `ctx.obj.get("verbose", False)` to respect the global `--verbose` flag.

Example:

```python
@app.command()
def my_command(ctx: typer.Context, arg: str):
    """Docstring becomes help text."""
    verbose = ctx.obj.get("verbose", False)
    if verbose:
        console.print(f"Running my_command with {arg}")
    ...
```

## Conventions

### Console output

Always use `Console(stderr=True)` so command output can be piped cleanly:

```python
from rich.console import Console
console = Console(stderr=True)
```

Use Rich tables, panels, and progress indicators for user-facing output.

### Typer apps

Set `no_args_is_help=True` on command groups so running the group alone shows help:

```python
app = typer.Typer(no_args_is_help=True)
```

### Environment variables

Use Typer's `envvar=` option for options that should be configurable via env vars:

```python
key: Annotated[str, typer.Option(envvar="GAAS_API_KEY", help="...")] = "..."
```

### Avoid shadowing built-ins

If a command name collides with a Python built-in (e.g., `list`), expose it via `typer.command("list")` and name the function something else:

```python
@app.command("list")
def list_items():
    """List items."""
    ...
```

### Document loaders

Document parsing lives in `src/gaas_cli/meili/document/loader.py`. It supports JSON, CSV, and Parquet from files or stdin.

### Pydantic validators

Reusable validators are in `src/gaas_cli/schema/utils.py`:

- `NaFloat` — float with `"na"`/`"nan"` handling
- `NaString` — string with empty/NA handling
- `CommaList` — comma-separated string to list

## Testing

Use `typer.testing.CliRunner` for command tests.

```python
from typer.testing import CliRunner
from gaas_cli.main import app

runner = CliRunner()

def test_hello():
    result = runner.invoke(app, ["newgroup", "hello", "World"])
    assert result.exit_code == 0
    assert "Hello World" in result.output
```

Mock external calls with `unittest.mock`:

```python
from unittest.mock import patch, MagicMock

def test_external_api():
    with patch("gaas_cli.api.requests.get") as mock_get:
        mock_get.return_value = MagicMock(json=lambda: {"status": "ok"}, status_code=200)
        assert fetch_status()["status"] == "ok"
```

## Versioning

Versions are derived from git tags matching `gaas-cli-*`.

```bash
git tag gaas-cli-v0.2.0
```

If `_version.py` is missing or stale, regenerate it:

```bash
hatch version
```

## Protected files

Do not edit manually:

- `src/gaas_cli/_version.py`
- `uv.lock`
- `dist/`

## Permission boundaries

- **DO** create admin/data-operation commands.
- **DO** use Pandas/PyArrow for data processing.
- **DO** integrate with MeiliSearch for search operations.
- **DO NOT** embed Galaxy API logic directly — use the `blendtype` HTTP layer instead.
- **DO NOT** access databases directly — use API endpoints.
- **DO NOT** handle user authentication — that lives in the Nuxt layer.
