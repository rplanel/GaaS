<objective>
Make sync lock TTL, batch size, and retry parameters configurable through the Nuxt module options so operators can tune the scheduled task without code changes.

Purpose: Hardcoded values in the scheduled task prevent operational tuning and make tests depend on magic numbers. Centralizing them in ModuleOptions follows the existing flat option style and keeps secrets out of public config.
Output: Updated module.ts, scheduled task, and syncAnalysisEffect signature, with a test verifying config propagation.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| nuxt.config / env → runtimeConfig | Sync options cross from config into the Nitro runtime; only private runtime config may contain tunable operational values. |
| Scheduled task → syncAnalysisEffect | Config values flow into lock TTL and batch size; incorrect values could affect resource usage. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-08-02-01 | Information Disclosure | module.ts runtime config | medium | mitigate | Keep all new sync options in RuntimeConfig (private), not PublicRuntimeConfig, so they are not serialized to the browser. |
| T-08-02-02 | Denial of Service | syncBatchSize / syncLockTtlSeconds | medium | mitigate | Provide sensible defaults (20, 900s) and validate that batchSize is positive; operators can override, but the module does not accept unbounded values from untrusted sources. |
| T-08-02-SC | Tampering | npm/pip/cargo installs | low | accept | No new packages are installed in this plan. |
</threat_model>
