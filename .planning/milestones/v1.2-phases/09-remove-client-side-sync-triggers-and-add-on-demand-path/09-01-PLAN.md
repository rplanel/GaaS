      - `GetSupabaseUserError` -> throw `createError({ statusCode: 401, statusMessage: 'Unauthorized' })`;

      - `ForbiddenError` -> throw `createError({ statusCode: 403, statusMessage: 'Forbidden' })`;
      - for any other error log with `useLogger(event).error('sync analysis handler failed', { cause: Cause.pretty(Cause.fail(error)) })` and throw 500.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Client browser -> Nitro API | Untrusted user input (route id, auth cookie) crosses here |
| API handler -> scheduled task | Handler must not mutate sync state directly; it enqueues the trusted task |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-09-01 | Tampering / Elevation of privilege | sync.post.ts owner check | high | mitigate | Fetch `analyses.owner_id` via service-role client and fail with 403 when it does not equal `getSupabaseUser(event).id`. |
| T-09-02 | Information disclosure | sync.post.ts error handling | medium | mitigate | Return generic 500 status/message to the client; log the cause only through evlog request logger, which applies production redaction. Do not log Galaxy API keys, JWTs, or Supabase service keys. |
| T-09-03 | Spoofing / Repudiation | sync.post.ts task enqueue | medium | mitigate | Enqueue only the fixed task name `galaxy:sync-analyses` with the validated integer `analysisId`; never pass user-controlled strings or objects to `runTask`. |
| T-09-04 | Denial of service | Client repeatedly clicking "Sync now" | low | accept | The handler returns immediately and the scheduled task's lock logic deduplicates work; abuse is bounded by auth and existing rate limits. Documented as accepted risk. |
</threat_model>
