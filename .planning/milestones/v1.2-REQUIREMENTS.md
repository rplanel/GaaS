# Requirements: GaaS — Galaxy Analysis Sync Hardening

**Defined:** 2026-08-07
**Core Value:** Developers can reliably build, deploy, and operate custom Galaxy-powered web interfaces with clear observability, because structured logging makes runtime behavior understandable to both humans and LLMs.

## v1 Requirements

### Audit

- [x] **AUDIT-01**: Inventory every call site of legacy `synchronize*Effect` helpers and every client-side sync trigger, documenting which are dead, which still run, and what data they mutate.
- [x] **AUDIT-02**: Confirm the canonical server-driven sync contract (`syncAnalysisEffect`, `syncJobEffect`, `syncOutputDatasetEffect`, `galaxy:sync-analyses` task) including inputs, outputs, lock semantics, and terminal-state rules.
- [x] **AUDIT-03**: Use evlog traces and code review to identify gaps in the current sync workflow (missing logs, race windows, unhandled error branches, partial writes).

### Refactor

- [x] **REFACTOR-01**: Make the Supabase-client server-driven sync path the single source of truth by removing the legacy Drizzle sync helpers (`synchronizeAnalysisEffect`, `synchronizeJobEffect`, `synchronizeHistoryEffect`, and old output helper) and migrating any remaining callers.
- [x] **REFACTOR-02**: Harden `sync_locks` acquisition to be atomic (e.g., `insert ... on conflict do nothing` / upsert) and make lock TTL and batch size configurable via module options.
- [x] **REFACTOR-03**: Add retry/backoff for transient Galaxy and Supabase failures inside the sync Effect program, and add `sync_attempts`, `last_sync_error_at`, and `next_sync_at` tracking to the `analyses` table.
- [x] **REFACTOR-04**: Ensure per-analysis failures do not crash the batch sync task and that locks are released via `Effect.addFinalizer` even on failure.

### Observability

- [x] **OBSERVE-01**: Emit structured evlog logs at every sync boundary: task start/end, lock acquire/release, invocation fetch, state transition, dataset download/upload, and all error paths.
- [x] **OBSERVE-02**: Annotate sync logs with `analysisId`, `ownerId`, `galaxyInvocationId`, `historyId`, `jobId`, and `datasetId` so traces are reconstructible.
- [x] **OBSERVE-03**: Ensure the scheduled task finalizer always emits a `taskLog.emit` wide event with `synced`, `failed`, `skipped`, `durationMs`, and error summary.
- [x] **OBSERVE-04**: Verify no secrets (Galaxy API keys, Supabase service keys, JWTs, dataset contents) are logged in sync paths or tests.

### Client Contract

- [x] **CLIENT-01**: Remove or redirect any client-side polling, composable, or component that triggers Galaxy sync outside the scheduled task.
- [x] **CLIENT-02**: Document that Supabase Realtime remains a display-only refresh mechanism and the server task owns sync state mutations.
- [x] **CLIENT-03**: Optionally expose a server action/handler that enqueues `galaxy:sync-analyses` with a single `analysisId` payload without bypassing locks.

### Test

- [x] **TEST-01**: Add tests covering lock contention (held lock → skip; expired lock → reclaim).
- [x] **TEST-02**: Add tests covering Galaxy unavailability (503 → retry succeeds; 503 × N → marked failed with `sync_attempts` incremented).
- [x] **TEST-03**: Add tests covering partial failure (DB write failure inside output sync → lock released, batch continues).
- [x] **TEST-04**: Add tests covering jobs-summary-derived terminal outcome and batch summary counts `{ synced, failed, skipped }`.

### Verify

- [x] **VERIFY-01**: Root `pnpm lint` passes after all changes.
- [x] **VERIFY-02**: Root `pnpm typecheck` passes after all changes.
- [x] **VERIFY-03**: Root `pnpm test` passes after all changes.

## v2 Requirements

Deferred to a future release.

### Advanced Scheduling

- **SCHED-01**: Replace the polling scheduled task with an event-driven queue (e.g., Supabase Edge Function webhooks from Galaxy or a proper job queue) to reduce polling overhead.
- **SCHED-02**: Support per-analysis priority and concurrency limits.

### Client Notifications

- **NOTIF-01**: Push terminal state notifications to connected clients via Supabase Realtime or WebSocket.

## Out of Scope

| Feature | Reason |
|---------|--------|
| New Galaxy API endpoints or blendtype schema changes unrelated to sync | Out of refactor scope; only fix sync-relevant blendtype usage. |
| UI redesign of analysis status pages | Client work deferred; only remove/redirect sync triggers. |
| Replacing evlog or adding new observability backend | Use existing evlog stack. |
| Adding Redis/BullMQ/pgmq/Temporal job queue | Keep within existing Nitro scheduled task + Supabase for v1.2. |
| Streaming upload implementation if not already present | Only harden existing dataset sync path; new streaming is v2+. |
