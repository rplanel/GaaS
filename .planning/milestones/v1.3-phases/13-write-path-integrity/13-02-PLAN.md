<objective>
Make the analysis delete path finalize a stranded `analysis_monitoring` row from `pending` to `cancelled` (WRIT-02).

Purpose: Deleting an analysis currently leaves any `pending` monitoring row stranded forever (the FK `analysis_id ON DELETE SET NULL` nulls the join column and the row never reaches a terminal outcome), which corrupts usage statistics with phantom `pending` counts. Wrapping the pending-guarded finalize + the `analyses` DELETE in one transaction, executed only after the external Galaxy history delete succeeds, keeps stats accurate while preserving the sync task as the sole terminal-state writer for all non-delete transitions.

Output:
- `finalizeAnalysisMonitoringEffect` — a pending-guarded UPDATE of `analysis_monitoring` located by `analysisId` + `ownerId`, returning the updated row or `undefined` on a 0-row no-op.
- `deleteAnalysis` runs finalize + delete in one `useDrizzle.transaction`, after `bt.deleteHistoryEffect`, and emits an evlog line after a successful finalize.
</objective>
