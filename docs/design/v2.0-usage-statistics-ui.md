# v2.0 Usage Statistics UI — design brief

Outcome of a grilling session on 2026-09-17. Every decision below was put to the maintainer and confirmed. Vocabulary is defined in `CONTEXT.md`; the one architecture decision is `docs/adr/0001-usage-statistics-server-filtered-observable-plot.md`. This brief is the input to the v2.0 milestone planning.

## Scope

In: UIAU-01 (own usage dashboard), UIAU-02 (global usage dashboard), UIAU-03 (time-range and workflow filters), plus updating the Galaxy module documentation page for the new endpoint parameters.

Explicit no's: per-user breakdown, drilldown to analyses, export, realtime, hourly buckets, a time zone parameter, cross-version workflow filtering, a success-rate line, Mosaic, disk usage inside the shared component. The user-facing docs section waits for the regular docs pass.

## Galaxy module (`nuxt-galaxy`)

- Both usage endpoints accept optional `from`, `to`, `granularity` (day | week | month) and `workflowId` (integer, or the literal `unknown`). Absent parameters keep today's meaning: all time, daily buckets.
- The time range filters on when an analysis started and applies to counts, trend and per-workflow usage alike.
- The workflow filter applies to counts and trend only. Per-workflow usage always lists every workflow in range so the table can serve as the picker.
- Buckets stay UTC. Every success rate still comes from the single `computeSuccessRate` helper.
- Client query definitions follow the existing Pinia Colada pattern under `runtime/app/queries`.
- Server tests stay DB-free, matching v1.3.

## UI layer (`@gaas/ui`)

Routes and navigation
- One shared component rendered on `/profile/usage` (own usage) and `/admin/usage` (global usage).
- Admin index gets a third card and the admin navigation a third child, both "Usage". The user menu gets a "Usage" entry next to "Profile".
- The profile page becomes a hub: an Account section (keeps disk usage) and a Usage section with two unfiltered tiles, total and success rate, linking to `/profile/usage`.

The shared component
- Six tiles: total, Succeeded, Failed, Cancelled, Pending, success rate.
- Trend: stacked bars per bucket, one segment per outcome, all four outcomes shown. Drawn with Observable Plot through the existing SSR render shim. Axis labelled UTC.
- Per-workflow table: sortable, four counts plus rate, doubles as the workflow picker. "Unknown workflow" is a selectable row. The selected row is highlighted.
- Success rate with no completed analyses shows a dash with "No completed analyses yet" on hover, in tiles, rows and buckets alike.

Filters
- Presets: last 7, 30 and 90 days, and all time. Custom range available.
- Default: last 30 days by day. The UI always sends parameters; the API default differs by design.
- Granularity chosen automatically from range length (day to about 90 days, week to about two years, month beyond) with a manual override.
- Workflow filter keyed on the specific workflow version (local id). Picker options come from the response, never from the live workflows table, so deleted workflows remain selectable.
- All filter state lives in the URL: the preset token while a preset is active, absolute dates for a custom range.

States and behaviour
- Empty account: the existing "no analyses" pattern pointing at the workflows page.
- Data loads on entry and on filter change, with a manual refresh button. No realtime.
- Gating: existing client role check plus the 403 the admin endpoint already returns.
- Component tests with a mocked query, following `packages/ui/test/components`.
