GaaS UI is a Nuxt layer built on top of `nuxt-galaxy` that provides pre-built pages and layouts.
It simplifies the process of creating a user interface for your Galaxy-based applications
by offering ready-to-use components and layouts.

It provides a set of pages, components, and layouts to build a user interface
that consume the `nuxt-galaxy` server API.

- Take advantage of the galaxy tool description to generate forms.
- It uses the Galaxy tool description (Galaxy tool xml file or wrapper)
to generate a form to invoke a workflow.

::warning
Only a subset of the rich Galaxy tool description is supported.
::

## Supabase Integration

GaaS UI extends `nuxt-galaxy`, which automatically configures `@nuxtjs/supabase`. The UI layer inherits all Supabase functionality:

- **Typed Supabase client** — Use `useSupabaseClient<Database>()` with full TypeScript types
- **Auth pages** — Login, signup, password recovery pages included
- **Role-based navigation** — `useUserRole()` drives menu visibility
- **Storage integration** — File upload via `useUploadFileToStorage()`

### Configuration

In your app's `nuxt.config.ts`:

```typescript [nuxt.config.ts]
export default defineNuxtConfig({
  extends: ['@gaas/ui'],
  // nuxt-galaxy is auto-registered by the UI layer
})
```

::note
The UI layer sets `supabase: { types: false }` to disable default type generation, because `nuxt-galaxy` provides its own typed `database.ts`.
::

### Auth Pages

The UI layer provides complete authentication flows:

| Page | Route | Description |
|------|-------|-------------|
| Login | `/login` | Email/password + GitHub OAuth |
| Signup | `/signup` | New account registration |
| Confirm | `/confirm` | Email verification |
| Profile | `/profile` | User profile management |

### Role-Based UI

Components use `useUserRole()` to show/hide features:

```vue [Navigation]
<script setup>
const supabase = useSupabaseClient<Database>()
const { userRole } = useUserRole(supabase)

const isAdmin = computed(() => userRole.value === 'admin')
</script>

<template>
  <UNavigationMenu
    :items="[
      { label: 'Workflows', to: '/workflows' },
      { label: 'Analyses', to: '/analyses' },
      ...(isAdmin ? [{ label: 'Admin', to: '/admin' }] : []),
    ]"
  />
</template>
```

### Sign-in Redirects

The UI layer sets the sign-in redirects for its own pages:

- a signed-out visitor is sent to `/login`, and signs in through `/confirm`;
- the page they were on is saved to a cookie, and login and confirm send them back to it;
- `/`, `/login`, `/signup` and `/confirm` are public pages, which a signed-out visitor can reach.

To add public pages of your own, list them in your app's `exclude`. Nuxt concatenates the two lists, so the layer's four stay public. The type of `redirectOptions` requires `login` and `callback`, so repeat the layer's:

```typescript [nuxt.config.ts]
export default defineNuxtConfig({
  extends: ['@gaas/ui'],
  supabase: {
    redirectOptions: {
      login: '/login',
      callback: '/confirm',
      exclude: ['/about', '/wiki', '/wiki/**'],
    },
  },
})
```

### Layer Dependency

```
Your App
├─ extends: ['@gaas/ui']
│  ├─ extends: nuxt-galaxy (auto-registered)
│  │  ├─ @nuxtjs/supabase
│  │  ├─ @pinia/nuxt and @pinia/colada-nuxt
│  │  └─ Drizzle ORM
│  └─ @nuxt/ui
```
