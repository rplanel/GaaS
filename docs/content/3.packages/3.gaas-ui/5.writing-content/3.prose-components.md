### Accordion

Use `accordion` and `accordion-item` to create collapsible content sections. Accordions are useful for organizing FAQs, expandable details, or grouped information in an interactive way.

::code-preview
---
class: "[&>div]:*:my-0"
---
  :::accordion
    ::::accordion-item
    ---
    icon: i-lucide-circle-help
    label: What is the GaaS wiki?
    ---
    The GaaS wiki is part of GaaS UI and provides comprehensive documentation and wiki capabilities using Nuxt Content. It allows you to create and manage content easily within your Galaxy workflow interface.
    ::::

    ::::accordion-item
    ---
    icon: i-lucide-circle-help
    label: How do I add content to my wiki?
    ---
    You can write `.md` or `.yml` files in the `content/` directory. The navigation will be automatically generated. Check out the [Writing Content](/packages/gaas-ui/writing-content) guides for detailed syntax.
    ::::

    ::::accordion-item{icon="i-lucide-circle-help" label="What components are available?"}
    The GaaS wiki provides a rich set of prose components including accordions, callouts, cards, tabs, steps, code blocks, and more. All components support full Markdown and are styled consistently with the GaaS design system.
    ::::
  :::

#code
```mdc
::accordion

:::accordion-item{label="What is the GaaS wiki?" icon="i-lucide-circle-help"}
The GaaS wiki is part of GaaS UI and provides comprehensive documentation and wiki capabilities using Nuxt Content. It allows you to create and manage content easily within your Galaxy workflow interface.
:::

:::accordion-item{label="How do I add content to my wiki?" icon="i-lucide-circle-help"}
You can write `.md` or `.yml` files in the `content/` directory. The navigation will be automatically generated. Check out the [Writing Content](/packages/gaas-ui/writing-content) guides for detailed syntax.
:::

:::accordion-item{label="What components are available?" icon="i-lucide-circle-help"}
The GaaS wiki provides a rich set of prose components including accordions, callouts, cards, tabs, steps, code blocks, and more. All components support full Markdown and are styled consistently with the GaaS design system.
:::

::
```

### Callout

Use callout to emphasize important contextual information. Callouts draw attention to notes, tips, warnings, or cautions, making key information stand out.

Customize with `icon` and `color` props or use `note`, `tip`, `warning`, `caution` shortcuts for pre-defined semantic styles.

::code-preview
---
class: "[&>div]:*:my-0 [&>div]:*:w-full"
---
  :::callout
  This is a `callout` with full **markdown** support.
  :::

#code
```mdc
::callout
This is a `callout` with full **markdown** support.
::
```

### Card

Use `card` to highlight content blocks. Cards are useful for showcasing features, resources, or related information in visually distinct and interactive containers.

Customize with `title`, `icon`, and `color` props. Cards can also act as links using `<NuxtLink>` properties for navigation.

::code-preview
---
class: "[&>div]:*:my-0 [&>div]:*:w-full"
---
  :::card
  ---
  icon: i-simple-icons-github
  target: _blank
  title: Blendtype
  to: https://github.com/rplanel/GaaS/tree/main/packages/blendtype
  ---
  TypeScript client for the Galaxy REST API.
  :::

#code
```mdc
::card
---
title: Blendtype
icon: i-simple-icons-github
to: https://github.com/rplanel/GaaS/tree/main/packages/blendtype
target: _blank
---

::
```

### Field

Use `field` to describe a specific field, property, or parameter. `field` components are perfect for documenting API parameters, component props, or configuration options.

::code-preview
  :::field{.w-full required name="name" type="string"}
  The `description` can be set as prop or in the default slot with full **markdown** support.
  :::

#code
```mdc
::field{name="name" type="string" required}
The `description` can be set as prop or in the default slot with full **markdown** support.
::
```
::

### FieldGroup

Use `field-group` to group related fields together in a list. `field-group` helps organize and structure documentation for multiple related fields or properties.

::code-preview
  :::field-group
    ::::field{name="analytics" type="boolean"}
    Default to `false` - Enables analytics for your project (coming soon).
    ::::

    ::::field{name="blob" type="boolean"}
    Default to `false` - Enables blob storage to store static assets, such as images, videos and more.
    ::::

    ::::field{name="cache" type="boolean"}
    Default to `false` - Enables cache storage to cache your server route responses or functions using Nitro's `cachedEventHandler` and `cachedFunction`
    ::::

    ::::field{name="database" type="boolean"}
    Default to `false` - Enables SQL database to store your application's data.
    ::::
  :::

#code

### Steps

Use `steps` to create step-by-step guides from document headings. `steps` component automatically numbers headings, creating a numbered guide for processes and tutorials.

Set the `level` prop to define the heading level to include in the step-by-step guide.

::code-preview
---
class: "[&>div]:*:w-full"
---
  :::steps{level="4"}
  #### Add the `@gaas/ui` layer in your `nuxt.config.ts`

  ```ts [nuxt.config.ts]
  export default defineNuxtConfig({
    extends: ['@gaas/ui']
  })
  ```

  #### Import Tailwind CSS and `@nuxt/ui` in your CSS

  ```css [assets/css/main.css]
  @import "tailwindcss";
  @import "@nuxt/ui";
  ```
  :::

#code
````mdc
::steps{level="4"}

#### Add the `@gaas/ui` layer in your `nuxt.config.ts`{lang="ts-type"}

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  extends: ['@gaas/ui']
})
```

#### Import Tailwind CSS and `@nuxt/ui` in your CSS

```css [assets/css/main.css]
@import "tailwindcss";
@import "@nuxt/ui";
```

::
````
