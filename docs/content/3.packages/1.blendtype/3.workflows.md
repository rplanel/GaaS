## Listing Workflows

Get all available workflows on the Galaxy server.

::code-group

```typescript [Promise]
import { getWorkflows } from 'blendtype'

const workflows = await getWorkflows()
console.log(`Found ${workflows.length} workflows`)

for (const workflow of workflows) {
  console.log(`- ${workflow.name} (${workflow.id})`)
}
```

```typescript [Effect]
import { getWorkflowsEffect } from 'blendtype'
import { Effect } from 'effect'

const program = Effect.gen(function* () {
  const workflows = yield* getWorkflowsEffect()
  yield* Effect.log(`Found ${workflows.length} workflows`)
  return workflows
})
```

::

### Hidden stored workflows

Galaxy's `GET /api/workflows` applies `hidden == show_hidden`: by default it lists the visible stored workflows only, and with `show_hidden=true` it lists only the hidden ones. Hidden is a display flag of Galaxy's own workflow list and says nothing about whether a workflow can be published or run, so a caller that wants every stored workflow of the account asks for both:

```typescript
const all = await getWorkflows(layer, { includeHidden: true })
// the visible ones first, then the hidden ones, each carrying `hidden`
```

Deleted stored workflows are never listed. Galaxy deletes softly and still describes a deleted one by id, `deleted: true`, which is how a reader tells one that is gone.

## Getting a Workflow

Fetch the full definition of a specific workflow, including its inputs and steps.

```typescript [Promise]
import { getWorkflow } from 'blendtype'

const workflow = await getWorkflow('workflow-123')
console.log(workflow.name) // "RNA-seq Pipeline"
console.log(workflow.version) // 2

// Access inputs
const inputs = workflow.inputs
console.log(Object.keys(inputs)) // ["0", "1"]
```

### Workflow Structure

The `GalaxyWorkflow` type includes:

| Property | Type | Description |
|----------|------|-------------|
| `id` | `string` | Galaxy workflow ID |
| `name` | `string` | Workflow display name |
| `version` | `number` | Workflow version |
| `inputs` | `Record<string, WorkflowInput>` | Input definitions |
| `steps` | `Record<string, WorkflowStep>` | Processing steps |
| `published` | `boolean` | Is published |
| `tags` | `TagCollection` | User tags |

## Listing a Workflow's Revisions

Every save of a stored workflow in Galaxy appends a **revision**; the workflow keeps its name and its identifier. `getWorkflowRevisions` lists them as Galaxy indexes them, oldest first, one entry per revision with its 0-based index as `version`, when it was saved and how many steps it has. GaaS publishes a version by choosing one of these revisions and giving it a label (ADR 0004).

::code-group

```typescript [Promise]
import { getWorkflowRevisions } from 'blendtype'

const revisions = await getWorkflowRevisions('workflow-123', layer)
// [
//   { version: 0, update_time: '2026-09-01T10:00:00', steps: 3 },
//   { version: 1, update_time: '2026-09-10T08:30:00', steps: 4 },
// ]

const latest = revisions.reduce((a, b) => (b.version > a.version ? b : a))
```

```typescript [Effect]
import { getWorkflowRevisionsEffect } from 'blendtype'
import { Effect } from 'effect'

const program = Effect.gen(function* () {
  const revisions = yield* getWorkflowRevisionsEffect('workflow-123')
  yield* Effect.log(`${revisions.length} revisions`)
  return revisions
})
```

::

| Property | Type | Description |
|----------|------|-------------|
| `version` | `number` | The 0-based index of the revision. The same integer `exportWorkflow` and `invokeWorkflow` take as their `revision` |
| `update_time` | `string` | When the revision was saved |
| `steps` | `number` | How many steps the revision has |

::note
Read the index off each entry's `version`, never off its position in the list. It is the integer that names the revision everywhere else in the Galaxy API.
::

Galaxy's editor shows the same revision to a person as `version + 1`, so the API's revision 3 is "4" in the editor. `galaxyRevisionNumber(index)` gives that number; use it for anything a person reads, and keep the index for anything that travels.

```typescript
import { galaxyRevisionNumber } from 'blendtype'

galaxyRevisionNumber(3) // 4, what the editor calls the revision the API indexes as 3
```

## Invoking a Workflow

Start a workflow execution with input datasets and parameters.

```typescript [Promise]
import { invokeWorkflow } from 'blendtype'

const invocation = await invokeWorkflow(
  'history-123', // Target history ID
  'workflow-456', // Workflow ID
  { // Input datasets
    0: { id: 'dataset-1', src: 'hda' },
    1: { id: 'dataset-2', src: 'hda' }
  },
  { // Tool parameters
    'tool-1': { 'param-name': 'value' }
  }
)

console.log(`Invocation ID: ${invocation.id}`)
console.log(`State: ${invocation.state}`)
```

::note
Input datasets use the `hda` (History Dataset Association) source type by default.
::

## Exporting a Workflow

Download a workflow as a shareable file. Blendtype validates the export with Zod.

```typescript [Promise]
import { exportWorkflow } from 'blendtype'

// Export the latest revision, in the default (ga) format
const exported = await exportWorkflow('workflow-123', layer)
console.log(exported) // Workflow definition object
console.log(exported.version, exported.uuid) // the revision's index and identifier

// Export one revision by its index, as listed by getWorkflowRevisions
const older = await exportWorkflow('workflow-123', layer, 'export', 1)
console.log(older.version) // 1
```

Galaxy exports the latest revision unless a `revision` is given, so `exportWorkflow('workflow-123', layer)` and `exportWorkflow('workflow-123', layer, 'export', undefined)` are the same request. The export carries two fields naming the revision it is of: `version`, the 0-based index, and `uuid`, the identifier Galaxy gave that revision when it was saved. An export missing either is refused as not a Galaxy export.

## Tag Helpers

Read a `name:` or a `version:` tag off a stored workflow's tags, or `null` when there is none. Tags decide nothing in GaaS: a workflow's name and version are what an administrator publishes for one revision, typed in the publish dialog (ADR 0004). The dialog uses these two helpers to pre-fill its fields when the stored workflow happens to carry the tags, and that is their only use.

```typescript
import { getWorkflowTagName, getWorkflowTagVersion } from 'blendtype'

const tags = ['version:2.0', 'name:RNA-seq', 'production']

const version = getWorkflowTagVersion(tags)
console.log(version) // "2.0", offered as the label

const name = getWorkflowTagName(tags)
console.log(name) // "RNA-seq", offered as the name
```

## Complete Example: Run Analysis Pipeline

```typescript [pipeline.ts]
import {
  createHistoryEffect,
  getWorkflowEffect,
  invokeWorkflowEffect,
  makeGalaxyLayer,
  uploadFileToHistoryFromBufferEffect
} from 'blendtype'
import { Effect, pipe } from 'effect'

const layer = makeGalaxyLayer({ url: '...', apiKey: '...' })

const pipeline = pipe(
  Effect.gen(function* () {
    // Fetch workflow definition
    const workflow = yield* getWorkflowEffect('workflow-abc')
    yield* Effect.log(`Running workflow: ${workflow.name}`)

    // Create history
    const history = yield* createHistoryEffect('Automated Analysis')

    // Upload input data
    const dataset = yield* uploadFileToHistoryFromBufferEffect({
      historyId: history.id,
      buffer: myBuffer,
      name: 'input.fastq'
    })

    // Invoke workflow
    const invocation = yield* invokeWorkflowEffect(
      history.id,
      workflow.id,
      { 0: { id: dataset.id, src: 'hda' } },
      {}
    )

    return { workflow: workflow.name, history: history.id, invocation: invocation.id }
  }),
  Effect.provide(layer)
)

Effect.runPromise(pipeline)
  .then(result => console.log('Pipeline complete:', result))
  .catch(error => console.error('Pipeline failed:', error))
```
