## Service Pattern: Context.Tag

Blendtype models its dependencies as services using Effect's `Context.Tag`. This is the foundation of testability and composability.

### GalaxyFetch Service

The HTTP client is a service, not a global import:

```typescript [galaxy.ts]
export class GalaxyFetch extends Context.Tag('@blendtype/GalaxyFetch')<
  GalaxyFetch,
  ReturnType<typeof $fetch.create>
>() {
  static readonly Live = Layer.effect(
    GalaxyFetch,
    Effect.gen(function* () {
      const { apiKey, url } = yield* BlendTypeConfig
      return $fetch.create({
        baseURL: url,
        headers: { 'x-api-key': apiKey }
      })
    })
  )
}
```

Benefits:
- **Testable**: Replace `GalaxyFetch` with a mock in tests
- **Composable**: Combine with other services
- **Type-safe**: The Effect type system tracks which services are required

### Layer Composition

Combine configuration and HTTP client into a single layer:

```typescript
import { makeGalaxyLayer } from 'blendtype'

const layer = makeGalaxyLayer({
  url: 'https://usegalaxy.org',
  apiKey: 'your-key'
})
// Returns: Layer<GalaxyFetch | BlendTypeConfig>
```

## Retry Logic

All GET operations include automatic retry for transient failures.

### withRetry

```typescript [galaxy.ts]
export const defaultRetryPolicy = Schedule.exponential('100 millis').pipe(
  Schedule.intersect(Schedule.recurs(3))
)

export function withRetry<A, E, R>(effect: Effect<A, E, R>) {
  return effect.pipe(
    Effect.retry({
      schedule: defaultRetryPolicy,
      while: error => isRetryableError(error) // 429 or 503
    })
  )
}
```

Behavior:
- **Backoff**: Exponential starting at 100ms (100ms, 200ms, 400ms)
- **Max retries**: 3 attempts
- **Retryable**: Only 429 (Too Many Requests) and 503 (Service Unavailable)
- **Non-retryable**: POST, DELETE, PUT operations (mutations don't retry)

## Cleanup on Failure

Upload operations automatically clean up by deleting the history if the upload fails:

```typescript [histories.ts]
Effect.catchAll(error =>
  deleteHistoryEffect(historyId).pipe(
    Effect.flatMap(() => Effect.fail(error))
  )
)
```

This prevents orphaned histories with failed uploads.

## Effect Composition

Build complex pipelines by composing simple effects.

### Sequential Composition

```typescript
const pipeline = Effect.gen(function* () {
  const history = yield* createHistoryEffect('Analysis')
  const dataset = yield* uploadFileToHistoryFromUrlEffect({
    historyId: history.id,
    srcUrl: 'https://example.com/sample.fastq',
    name: 'sample.fastq'
  })
  const invocation = yield* invokeWorkflowEffect(history.id, '...', {
    inputs: { input1: dataset.id }
  })
  return { history, dataset, invocation }
})
```

### Parallel Composition

```typescript
import { Effect, ReadonlyArray } from 'effect'

// Upload multiple files in parallel
const uploads = ReadonlyArray.map(files, file =>
  uploadFileToHistoryFromBufferEffect({
    historyId: 'history-123',
    buffer: file.buffer,
    name: file.name
  }))

const results = yield * Effect.all(uploads)
```

### TUS as Async Effect

The TUS upload wraps callback-based `tus-js-client` into an Effect:

```typescript
function uploadWithTus(source, endpoint, metadata, apiKey, chunkSize) {
  return Effect.async((resume) => {
    const upload = new tus.Upload(source, {
      endpoint,
      metadata: { ...metadata, apiKey },
      chunkSize,
      onError: error => resume(
        Effect.fail(new TusUploadError({ message: error.message }))
      ),
      onSuccess: () => resume(
        Effect.succeed(upload.url)
      )
    })
    upload.start()
  })
}
```

## Provider Pattern

When to use `.pipe(Effect.provide(layer))`:

```typescript
// Option 1: Provide at the end (composition)
const piped = program.pipe(
  Effect.provide(layer),
  Effect.runPromise
)

// Option 2: Provide inline (immediate execution)
const result = await Effect.runPromise(
  Effect.provide(operation, layer)
)
```

::tip
**Separation of concerns**: Define the effect pipeline without the layer, then provide it at the composition boundary. This makes the pipeline reusable across different configurations.
::
