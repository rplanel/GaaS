## Tagged Error Types

Blendtype uses Effect-TS `Data.TaggedError` for domain-specific errors. Each error type carries context for debugging.

### Domain Errors

| Error | Context Fields | When Thrown |
|-------|---------------|-------------|
| `WorkflowError` | `workflowId`, `message`, `statusCode?`, `cause?` | Workflow CRUD, invoke, export failures |
| `HistoryError` | `historyId`, `message`, `statusCode?`, `cause?` | History operations |
| `DatasetError` | `datasetId`, `historyId`, `message`, `statusCode?`, `cause?` | Dataset operations |
| `ToolError` | `toolId`, `message`, `statusCode?`, `cause?` | Tool discovery |
| `JobError` | `jobId`, `message`, `statusCode?`, `cause?` | Job monitoring |
| `InvocationError` | `invocationId`, `message`, `statusCode?`, `cause?` | Invocation tracking |
| `ConfigError` | `message`, `cause?` | Missing/invalid configuration |
| `GalaxyServiceUnavailable` | `message` | Galaxy returns 503 |

### Generic Errors

| Error | Purpose |
|-------|---------|
| `GalaxyApiError` | Base API error with `statusCode` and `cause` |
| `TusUploadError` | TUS upload failures |
| `HttpError` | Generic HTTP failures |
| `NotImplemented` | Placeholder for unimplemented features |

## Type Guards

Check error types at runtime:

```typescript
import {
  isGalaxyApiError,
  isHistoryError,
  isWorkflowError
} from 'blendtype'

try {
  await getWorkflow('bad-id')
}
catch (error) {
  if (isWorkflowError(error)) {
    console.log(`Workflow: ${error.workflowId}`)
    console.log(`Status: ${error.statusCode}`)
  }

  if (isGalaxyApiError(error)) {
    console.log(`API Error: ${error.statusCode}`)
  }
}
```

## Effect Composition: catchTag

Handle specific errors in Effect pipelines:

```typescript
import { GalaxyServiceUnavailable, WorkflowError } from 'blendtype'
import { Effect } from 'effect'

const safeProgram = Effect.gen(function* () {
  const workflow = yield* getWorkflowEffect('id-123')
  return workflow
}).pipe(
  Effect.catchTag('WorkflowError', (error) => {
    yield * Effect.logError(`Workflow failed: ${error.message}`)
    return Effect.fail(new Error('Unavailable'))
  }),
  Effect.catchTag('GalaxyServiceUnavailable', (error) => {
    yield * Effect.logError('Galaxy is down, retry later')
    return Effect.fail(error)
  })
)
```

## Error Utilities

### Extract Status Codes

```typescript
import { extractStatusCode } from 'blendtype'

const status = extractStatusCode(error)
// Returns: number | undefined
```

### Format Messages

```typescript
import { formatErrorMessage } from 'blendtype'

const message = formatErrorMessage(
  'workflow', // Resource type
  'workflow-123', // Resource ID
  'invoke', // Action
  cause // Original error
)
// "Failed to invoke workflow workflow-123: ..."
```

## Promise Error Handling

When using the Promise API, errors are plain objects:

```typescript
try {
  await createHistory('My Analysis')
}
catch (error) {
  if (isHistoryError(error)) {
    console.error(`History error: ${error.message}`)
  }
  else {
    console.error(`Unexpected: ${error}`)
  }
}
```

::warning
The Promise API wraps errors in `FiberFailure`. Use `isXxxError()` type guards instead of `instanceof` checks.
::
