## Tool Discovery

Query Galaxy tools and inspect their parameters before using them in workflows.

### Get Tool Definition

```typescript [Promise]
import { getTool } from 'blendtype'

// Fetch tool with full parameter details
const tool = await getTool('tool-galaxy-id', '1.0.0')

console.log(tool.name) // Tool display name
console.log(tool.description) // Tool description
console.log(tool.version) // "1.0.0"
```

::note
The version travels as Galaxy's `tool_version` query parameter. Galaxy answers with the tool at that version when it holds it, but when it holds the tool only at other versions it answers **200 with the newest of them** rather than 404; 404 means it holds no version at all. A caller that needs the exact version, as publishing a version does, reads the answer's `version` and compares. The version is URL-encoded on the way: toolshed versions carry a `+` (`1.2.3+galaxy0`), and a raw `+` in a query string is a space to Galaxy.
::

### Tool Parameters

Each tool has strongly typed parameters. Understanding these is key to invoking workflows correctly.

```typescript
type GalaxyToolParameterType
  = | 'select' // Dropdown selection
    | 'boolean' // On/off switch
    | 'data' // Dataset input
    | 'float' // Decimal number
    | 'integer' // Whole number
    | 'conditional' // Conditional branch
```

Example: Inspecting a tool's parameters

```typescript [Promise]
import { getTool } from 'blendtype'

const tool = await getTool('trimmomatic', '0.38.0')

for (const param of tool.inputs) {
  console.log(`${param.name} (${param.type}): ${param.label}`)

  if (param.type === 'select') {
    console.log('  Options:', param.options)
  }

  if (param.type === 'data') {
    console.log('  Accepts:', param.extensions) // ["fastq", "fastqsanger"]
  }
}
```

::note
Always specify the tool version to ensure reproducibility. Tool definitions can change between versions.
::

## Job Monitoring

Track the status of Galaxy jobs with full details.

### Get Job Details

```typescript [Promise]
import { getJob } from 'blendtype'

const job = await getJob('job-789')

console.log(job.state) // "ok", "error", "running", etc.
console.log(job.command_line) // Executed command
console.log(job.exit_code) // 0 for success
```

### Job States

| State | Meaning |
|-------|---------|
| `ok` | Completed successfully |
| `error` | Failed with an error |
| `queued` | Waiting to execute |
| `running` | Currently executing |
| `paused` | Paused by user or system |
| `deleted` | Deleted by user |

### Job Metrics

When available, jobs include performance metrics:

```typescript
const job = await getJob('job-789')

for (const metric of job.job_metrics || []) {
  console.log(`${metric.title}: ${metric.value}`)
  // "CPU Time: 45.2s"
  // "Memory: 2.1GB"
}
```

## Invocation Tracking

Monitor workflow invocations and their step-by-step progress.

### Get Invocation Status

```typescript [Promise]
import { getInvocation } from 'blendtype'

const invocation = await getInvocation('invocation-abc')

console.log(invocation.state) // "scheduled", "new", "ok"
console.log(invocation.workflow_id)
console.log(invocation.history_id)
```

### Invocation Steps

Each invocation contains a list of steps:

```typescript
const invocation = await getInvocation('invocation-abc')

for (const step of invocation.steps) {
  console.log(`Step ${step.order_index}: ${step.state}`)

  if (step.job_id) {
    console.log(`  Job: ${step.job_id}`)
  }

  if (step.state === 'error') {
    console.log(`  ERROR: Check job ${step.job_id} for details`)
  }
}
```

### Invocation States

| State | Description |
|-------|-------------|
| `new` | Just created |
| `scheduled` | Queued for execution |
| `ok` | All steps completed successfully |
| `error` | One or more steps failed |
| `cancelled` | Cancelled by user |

## Polling Pattern

A common pattern is to poll for job/invocation completion:

```typescript [Effect]
import { getInvocationEffect } from 'blendtype'
import { Effect, Schedule } from 'effect'

function waitForCompletion(invocationId: string) {
  return Effect.gen(function* () {
    const invocation = yield* getInvocationEffect(invocationId)

    if (invocation.state === 'ok') {
      yield* Effect.log('Workflow completed successfully!')
      return invocation
    }

    if (invocation.state === 'error') {
      yield* Effect.logError('Workflow failed')
      return yield* Effect.fail(new Error('Workflow failed'))
    }

    yield* Effect.log(`State: ${invocation.state} — polling...`)
    return yield* waitForCompletion(invocationId)
  }).pipe(
    // Retry every 5 seconds, max 60 times (5 minutes)
    Effect.delay('5 seconds')
  )
}
```

::note
For production polling, use `Effect.schedule` with a proper `Schedule` instead of recursive delay.
::
